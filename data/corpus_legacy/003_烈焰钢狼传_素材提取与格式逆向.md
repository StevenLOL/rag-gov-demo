## 3. DDT 归档格式规范

### 3.1 整体结构

```
偏移量        大小        说明
0x0000        4 字节      uint32 LE: 文件总数 (N = 1370)
0x0004        N*16 字节   目录项数组 (每项 16 字节)
0x0004+N*16   可变        连续数据区
```

数据区起始偏移 = `4 + N * 16 = 4 + 1370 * 16 = 21924` (0x55A4)

### 3.2 目录项结构 (16 字节)

```
偏移量   大小     说明
0        12 字节  文件名 (ASCII, null 填充至 12 字节)
12       4 字节   uint32 LE: 数据在归档中的绝对偏移量
```

### 3.3 文件大小计算

目录项**不存储文件大小**，文件 i 的大小通过相邻偏移量之差计算：

```
size[i] = offset[i+1] - offset[i]
```

最后一个文件的大小 = 归档总大小 - offset[last]

### 3.4 特殊情况

- 第 1 个目录项 (索引 0) 的偏移量 = 21924 (数据区起始)，文件名为空或占位
- 存在 1 个零字节文件 (offset[i] == offset[i+1])，提取时跳过
- 文件名全部大写，扩展名 3 字符

## 4. CMP 图片格式规范 (核心逆向成果)

### 4.1 文件头 (4 字节)

```
偏移量   大小     说明
0        2 字节   uint16 LE: 图片宽度 (像素)
2        2 字节   uint16 LE: 图片高度 (像素)
```

### 4.2 压缩数据流

文件头之后为**命令式 RLE 压缩数据流**，按行独立解码。每行以命令 `0xFF` (行结束) 终止。

### 4.3 命令集

| 命令字节 | 名称 | 后续字节 | 输出 |
|----------|------|----------|------|
| 0x00 | 零值连续 | 1 字节 count | 输出 count 个颜色索引 0 |
| 0x01 | 颜色连续 | 1 字节 count + 1 字节 color | 输出 count 个 color |
| 0x02 | 字面字节 | 1 字节 count | 原样复制 count 字节 |
| 0x03 | 字面双字 | 1 字节 count | 原样复制 count × 4 字节 |
| 0x04 | 双字+1字节 | 1 字节 count | 原样复制 count × 4 + 1 字节 |
| 0x05 | 双字+1字 | 1 字节 count | 原样复制 count × 4 + 2 字节 |
| 0x06 | 双字+字+字节 | 1 字节 count | 原样复制 count × 4 + 3 字节 |
| 0xFF | 行结束 | 无 | 填充当前行剩余像素为 0，切换到下一行 |
| 0x07-0xFE | 无操作 | 无 | 消耗命令字节但不输出 (正常数据不出现) |

### 4.4 解码算法伪代码

```python
def decode_cmp(data):
    width = uint16_le(data[0:2])
    height = uint16_le(data[2:4])
    output = bytearray(width * height)
    pos = 4  # 数据起始
    row = 0
    col = 0
    out_pos = 0

    while row < height and pos < len(data):
        cmd = data[pos]
        pos += 1

        if cmd == 0x00:  # 零值连续
            count = data[pos]; pos += 1
            for _ in range(count):
                output[out_pos] = 0; out_pos += 1
        elif cmd == 0x01:  # 颜色连续
            count = data[pos]; pos += 1
            color = data[pos]; pos += 1
            for _ in range(count):
                output[out_pos] = color; out_pos += 1
        elif cmd == 0x02:  # 字面字节
            count = data[pos]; pos += 1
            output[out_pos:out_pos+count] = data[pos:pos+count]
            pos += count; out_pos += count
        elif cmd == 0x03:  # 字面双字
            count = data[pos]; pos += 1
            n = count * 4
            output[out_pos:out_pos+n] = data[pos:pos+n]
            pos += n; out_pos += n
        elif cmd in (0x04, 0x05, 0x06):  # 双字+额外字节
            count = data[pos]; pos += 1
            extra = cmd - 0x03  # 0x04→1, 0x05→2, 0x06→3
            n = count * 4 + extra
            output[out_pos:out_pos+n] = data[pos:pos+n]
            pos += n; out_pos += n
        elif cmd == 0xFF:  # 行结束
            # 填充当前行剩余像素
            remaining = width - (out_pos - row * width)
            for _ in range(remaining):
                output[out_pos] = 0; out_pos += 1
            row += 1
        else:  # 0x07-0xFE: 无操作
            pass

    return output, width, height
```

### 4.5 验证实例

**TITLE00A.CMP** (640x480 标题画面) 开头数据：

```
00 FF 00 FF 00 82 FF ...
```

解码：
- `00 FF` → 命令 0x00, count=255 → 输出 255 个颜色 0
- `00 FF` → 命令 0x00, count=255 → 输出 255 个颜色 0
- `00 82` → 命令 0x00, count=130 → 输出 130 个颜色 0
- `FF` → 行结束

合计: 255 + 255 + 130 = **640 像素** (正好一行全黑)，与图片宽度完全吻合。

## 6. XMI 音乐格式

### 6.1 格式说明

XMI (Extended MIDI) 是基于 IFF (Interchange File Format) 容器的 MIDI 变体，由 Electronic Arts 定义。文件结构：

```
FORM XMI ← 顶层 IFF 块
  ├── CAT ← 类别容器
  │   └── XMID ← MIDI 数据块
  │       ├── EVNT ← MIDI 事件流
  │       └── TIMB ← 音色信息 (可选)
  └── RBRN ← 循环/重复信息 (可选)
```

### 6.2 转换方法

使用 Python 解析 IFF 容器，递归扫描所有 `XMID` 块，提取其中的 `EVNT` MIDI 事件流，转换为标准 MIDI 1.0 格式。

**关键**: XMID 块嵌套在 CAT 块内，不能只扫描顶层块，必须递归解析。

### 6.3 转换结果

23/23 首 XMI 全部成功转换为标准 MIDI 文件，保存在 `13_music_midi/`。

## 7. 调色板格式

### 7.1 MAINCOL.PAL

- 大小: 768 字节
- 格式: 256 色 × 3 字节 (R, G, B)
- 位深: VGA 6 位每通道 (0-63)
- 转 8 位公式: `v8 = (v6 << 2) | (v6 >> 4)` (等效于 `v6 * 255 / 63`)

### 7.2 输出

- `MAINCOL.ACT`: Photoshop 调色板格式 (768 字节)
- `palette_preview.png`: 16x16 调色板预览图

## 9. IDA 逆向工程过程

### 9.1 目标

`TESTIMG.EXE` — 535KB DOS/4GW 保护模式可执行文件。

### 9.2 工具

- IDA Pro 7.6 (`E:\BaiduNetdiskDownload\IDA7.6\idat.exe`)
- 批量反汇编输出: 6.39 MB ASM 文件

### 9.3 调用链追踪

```
CMP 加载器 sub_1AD5E
  ├── 读取 4 字节头 (width, height)
  └── 读取压缩数据到缓冲区
      ↓
Blit 包装器 sub_1B10C / sub_1B0CC
  ├── 计算屏幕目标位置 (x, y)
  └── 调用核心解码器
      ↓
核心解码器 sub_1DA3F  ← 关键函数
  ├── 命令式 RLE 逐行解码
  └── 写入目标帧缓冲区
```

### 9.4 sub_1DA3F 核心逻辑

函数签名推测:
```c
void __cdecl decode_cmp(
    uint8_t *src,       // [ebp+arg_0]  压缩数据流
    uint8_t *dst,       // [ebp+arg_4]  目标帧缓冲区
    int width,          // [ebp+arg_8]  图片宽度
    int height,         // [ebp+arg_C]  图片高度
    int dst_pitch       // [ebp+arg_10] 目标行间距 (640 - width)
);
```

关键汇编特征:
- 逐字节读取命令 (`mov al, [esi]`)
- 命令分发跳转表 (`jmp cs:off_xxxxx[eax*4]`)
- 行计数器 (`edx`) 与高度比较
- 行结束时添加目标行间距 (`add edi, [ebp+arg_10]`)

### 9.5 反汇编位置

- 文件: `reverse/MWOLF/TESTIMG.EXE.asm`
- sub_1DA3F: 第 22555-22671 行

## 10. 已验证死路 (避免重复尝试)

以下压缩算法变体均已测试并**确认不适用**，全部产生横向条纹花屏：

| 编号 | 算法 | 失败原因 |
|------|------|----------|
| 1 | 简单 (count, color) 对 RLE | 命令结构不同 |
| 2 | 16 位词 RLE (高字节=count, 低字节=color) | 命令结构不同 |
| 3 | PCX RLE (b >= 0xC0 为运行包) | 标记位不同 |
| 4 | 0 标记 RLE (b == 0 为运行包) | 标记位不同 |
| 5 | LZSS (多种窗口/偏移参数) | 非字典压缩 |
| 6 | 逐行简单 RLE | 缺少命令分发逻辑 |

**教训**: 对于自研格式，静态分析压缩数据结构只能缩小范围，最终必须通过反汇编可执行文件确认精确算法。

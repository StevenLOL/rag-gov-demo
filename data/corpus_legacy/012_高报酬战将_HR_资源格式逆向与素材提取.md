### 3.3 RLE解码算法（已确认正确！）

**突破过程：**
1. 最初尝试直接4bpp/8bpp渲染 → 噪声
2. 尝试zlib/deflate/LZSS解压 → 失败或全0
3. 尝试简单RLE（各种marker） → 噪声
4. **关键突破**：注意到RLE流中高位1字节(54.1%)和高位0字节(45.9%)比例接近1:1，推测是标准的"高位标记"RLE
5. 验证：行96(@12288-12415)全是0x81，由两个重复111次0x81的操作组成，确认RLE正确

**RLE算法：**
```
从@16开始读取RLE流：
- 高位1 (0x80-0xff): 重复操作
  count = byte & 0x7f  (0x80时count=128)
  重复下一字节count次
- 高位0 (0x00-0x7f): 字面量操作
  count = byte  (0x00时无操作)
  复制接下来count字节
```

**验证证据：**
- 行96全0x81（128字节），由@4062重复111次+@4064重复111次组成
- 纯色行位置：行16、32、64、96、160、208、224（<5唯一字节）
- 最常见纯色段长度：127字节(254像素)×22次、112字节(224像素)×10次、123字节(246像素)×10次
- RLE流字节频率：0x00(1274次)、0x80(798次)、0xff(689次)

### 3.5 为什么有条纹？分析与思考

**已知事实：**
1. RLE解压正确（行96全0x81验证）
2. 图像是4bpp 16色（RGB调色板16色）
3. 图像数据大小32768字节 = 256×256 4bpp
4. 纯色行位置正确（行16、32、64、96等）

**可能原因：**
1. **像素排列方式特殊**：不是标准的行优先4bpp打包，可能是某种自定义排列
2. **图像分块存储**：图像被分成多个块（如8×8或16×16瓦片），块内和块间的排列方式不同
3. **第二层编码**：RLE解压后的数据还有第二层编码（如差分编码、预测编码）
4. **颜色映射特殊**：4位颜色索引需要经过某种转换（如查表、异或）
5. **行顺序特殊**：行与行之间不是连续存储，可能有跳跃或交错

**最可能的方向：**
- 从MAIN.EXE反汇编找到GS解码函数（16位保护模式代码，capstone可用）
- 函数名`hloadGraph`@0x3f6cd（错误消息字符串）
- VGA Mode X写入函数@0x20e10已定位，调用者@0x20c05可能是图像绘制函数

## 10. 附录：GS RLE解码算法（Python实现）

```python
def rle_decode_gs(data, target_size):
    """
    高报酬战将GS格式RLE解码
    data: RLE压缩数据（从@16开始）
    target_size: 目标解压大小（头部@4-5字段）
    """
    result = bytearray()
    pos = 0
    while len(result) < target_size and pos < len(data):
        b = data[pos]
        pos += 1
        if b & 0x80:
            # 高位1：重复操作
            count = b & 0x7f  # 0x80时count=128
            if count > 0 and pos < len(data):
                val = data[pos]
                pos += 1
                result.extend([val] * count)
        else:
            # 高位0：字面量操作
            count = b  # 0x00时无操作
            if count > 0:
                result.extend(data[pos:pos+count])
                pos += count
    return bytes(result)
```

### 13.7 72369-49=72320精确匹配

ED0.GS RLE解码72369字节，**跳过前49字节后72320字节**：
- 72320 = 256 × 565 / 2（4bpp 256×565）
- 72320 = 320 × 226（8bpp 320×226）
- 72320 = 320 × 452 / 2（4bpp 320×452）

## 1. 数据在 JMC 块流中的组织

Huffman+LZ77 解压后（解压算法见主文档，unicorn 模拟 `lcall 0xff5:0x34ad`），TEST.JMC 的 331 个块中，
战场单位精灵以「**一个大块 + 一个配对表小块**」成对出现：

| 角色 | 块号（偶数表/奇数大块） | 大小 | 说明 |
|------|----------|------|------|
| 大块（精灵像素 RLE 集合） | 奇数块 203,205,…,243 | 40976–63840 B | 16（或13）个精灵的 RLE 数据连续打包 |
| 配对表（每精灵定位/尺寸） | 偶数块 204,206,…,244 | **96 B = 16 记录**（或 **78 B = 13 记录**） | 每条 6 字节 |

- 配对表块号 = 大块块号 + 1（如大块 `blk203` ↔ 配对表 `blk204`）。
- 加载位置（来自 `PLAY.EXE` 反汇编 @0xbe0f 附近）：
  - 大块解压到运行时段 `[0x402]:0`（`[0x402] = cs:[0x16] + 0x1100`，由 @0x1d9d 内存分配链确定）；
  - 配对表解压到主数据段 `DS=0x13f3` 的 `0x00de` 偏移处。

### 1.1 配对表记录格式（每条 6 字节，小端 u16×3）

| 偏移 | 字段 | 含义 |
|------|------|------|
| +0 | `off` (u16) | **段号（paragraph），不是字节偏移**。精灵 f 的 RLE 数据在大块内字节偏移 = `off × 16` |
| +2 | `b` (u16) | 精灵宽度（像素），如 95 / 86 / 106 / 132 / 57 / 51 / 148 |
| +4 | `c` (u16) | 精灵高度（像素/行数），如 75 / 78 / 85 / 68 / 63 / 32 / 65 |

反汇编依据（@0x1af7，帧号 f → bx = f×6）：

```asm
0x1af7: shl ax,1 ; mov bx,ax ; shl ax,1 ; add bx,ax   ; bx = f*6
0x1aff: mov si,[bx+0xde]    ; si = off（段号）
0x1b03: mov cs:[0x1554],si  ; 保存当前精灵段号
0x1b08: mov ax,[bx+0xe2]    ; ax = c（高） -> cs:[0x1c26], [0x4a4]
0x1b17: mov ax,[bx+0xe0]    ; ax = b（宽） -> cs:[0x1c24], [0x4a2]
```

**`off` 是段号**这一点是关键，反汇编依据在行扫描函数 @0x1c48：

```asm
0x1c48: mov si,cs:[0x1554]  ; si = off（段号）
0x1c4d: add si,[0x402]      ; si = 大块基段 + off  -> 该精灵独占一个段
0x1c51: mov ds,si
0x1c53: xor si,si           ; 段内偏移从 0 开始
```

验证：blk203 的 off = 0,220,447,673,…,3329，相邻间隔约 220 段 ≈ 3520 B，
16 个精灵 ×3520 ≈ 56320 B，与大块 56896 B 吻合。

## 2. 精灵 RLE 命令流（核心）

每个精灵在自己的段内（段:0 起）是一条**逐行 RLE 命令流**，解码目标是一块 `b × c` 的帧缓冲，
帧缓冲初始填充 `0xFFFF`（**0xFF = 透明像素**，见 @0xc714 `rep stosw 0xe1 字填 0xffff`）。

### 2.1 命令字节是「偶数编码」（最易踩的坑）

命令字节 **不是** 0–5 的连续命令号，而是 **偶数**：`命令号 = 命令字节 / 2`。
解释器主循环 `lodsb → mov bl,al → jmp cs:[bx + 跳转表基址]`，bx 直接用偶数字节索引，
跳转表每项 2 字节，因此奇数索引项是相邻两项字节拼接出的垃圾、永不会被命中。

| 命令字节 | 命令号 | 助记 | 参数 | 语义 |
|----------|--------|------|------|------|
| `0x00` | 0 | SKIP8  | 1 字节 `n` | 输出 `n` 个透明像素（0xFF），目标位置 `+= n` |
| `0x02` | 1 | SKIP16 | 2 字节 `n`(u16) | 输出 `n` 个透明像素 |
| `0x04` | 2 | COPY8  | 1 字节 `n` + `n` 字节像素 | 原样拷贝 `n` 个像素（调色板索引） |
| `0x06` | 3 | COPY16 | 2 字节 `n`(u16) + `n` 字节像素 | 原样拷贝 `n` 个像素 |
| `0x08` | 4 | NEWLINE | 2 字节参数（跳过） | **一行结束**，处理程序 `add si,2; ret`，目标换到下一行行首 |
| `0x0A` | 5 | END | **无参数** | **整个精灵结束**，处理程序直接 `ret`（不 add si,2） |
| 其他偶数 / 任意奇数 | — | — | — | 不会出现；出现即说明起点或编码理解错误 |

跳转表（主代码段偏移，文件偏移 = 0x400 + 该值）：

| 解释器 | 跳转表基址 | 用途 |
|--------|-----------|------|
| @0x1556 | @0x15a3 | 解码到帧缓冲（无裁剪），bp = 目标线性位置 |
| @0x1977 | @0x1a33 | 带 dx 左裁剪的解码（直接 blit） |
| @0x1a44 | @0x1aeb | 带 dx 裁剪变体 |
| @0x1c48 | @0x1ca3 | **行定位扫描**（只移动 si 不写像素，用于按行裁剪时定位源位置） |

四个表的命令号→处理程序布局完全一致（0=SKIP8,1=SKIP16,2=COPY8,3=COPY16,4=NEWLINE,5=END）。

### 2.2 参考解码实现（Python，逐字节、与汇编等价）

```python
import struct
def decode_sprite(big: bytes, off_seg: int, W: int, H: int):
    data = big[off_seg*16 : off_seg*16 + W*H*2 + 256]
    si = 0; rows = []; cur = bytearray()
    while True:
        cmd = data[si]; si += 1
        if   cmd == 0x00:                      # SKIP8
            n = data[si]; si += 1; cur += b'\xff'*n
        elif cmd == 0x02:                      # SKIP16
            n = struct.unpack_from('<H', data, si)[0]; si += 2; cur += b'\xff'*n
        elif cmd == 0x04:                      # COPY8
            n = data[si]; si += 1; cur += data[si:si+n]; si += n
        elif cmd == 0x06:                      # COPY16
            n = struct.unpack_from('<H', data, si)[0]
            cur += data[si+2:si+2+n]; si += 2+n
        elif cmd == 0x08:                      # NEWLINE（命令后有 2 字节参数，跳过）
            si += 2
            if len(cur) < W: cur += b'\xff'*(W-len(cur))   # 行尾补透明
            rows.append(bytes(cur[:W])); cur = bytearray()
            if len(rows) >= H: return rows
        elif cmd == 0x0A:                      # END（无参数，处理程序直接 ret）
            if cur:
                if len(cur) < W: cur += b'\xff'*(W-len(cur))
                rows.append(bytes(cur[:W]))
            return rows
        else:
            raise ValueError(f"bad cmd 0x{cmd:02x} at {si-1}, row {len(rows)}")
```

渲染：用 PAL1（768 B，6 位 VGA DAC，每通道 `<<2` 扩到 8 位）查表，值 `0xFF` 的像素 alpha=0（透明）。

### 2.3 实例：精灵 0 的开头（blk203）

```
00 5f  08 e1 00   00 5f  08 e1 00   ...（重复 7 组）
└SKIP8 n=95┘ └NEWLINE┘  └SKIP8 n=95┘ └NEWLINE┘
```

- `00 5f` = SKIP8，n=0x5F=95（跳过一整行宽，即整行全透明）；
- `08 e1 00` = NEWLINE（命令 0x08 + 2 字节参数 e1 00）。
- 连续 7 组 = 精灵顶部 7 行全空（骑兵精灵上半身为空，马从第 8 行起出现）。

这与解码结果完全一致：精灵 0 共 75 行、每行恰 95 像素，行 0–6 非透明像素数为 0，
行 7 起为 6、21、31、33… 自上而下逐步显现骑兵轮廓。

## 3. 完整解码调用链（PLAY.EXE 反汇编）

```
@0xbf29  call bx                       动作×方向分派（bx 来自分派表）
分派表   主代码段 0x1e0ce（文件 0x1e4ce），20 字节/动作、2 字节/方向
@0xc348  动作0绘制 → @0xc416 动画坐标循环 → @0xc629 帧步进
@0xc70b / @0xc790  帧绘制
   ├─ @0xc714 帧缓冲初始化：rep stosw 填 0xFFFF（透明）
   ├─ @0x149d / @0x14bf  解码变体 A / B（设 3 个行函数指针后 call @0x14db）
   └─ @0x3144 帧缓冲→显存透明 blit（0xFF 透明：repne scasb 找非透明段，call @0x15af 拷贝，逐行换段）
@0x14db  解码主循环
   ├─ call @0x1af7  源/宽高/裁剪设置（bx=f*6，读 off/b/c）
   └─ 每行 call cs:[bp+0x1c28]  行分派表（16 项）
行分派表 @0x1c28：
   标志 0/2/4/… → @0x1cb0（仅设 DS=精灵段、si=0）
   标志 1/3/5/9  → @0x1c48（裁剪行 RLE 扫描定位，跳转表 @0x1ca3）
   标志 7/11–15  → @0x1cbe（块拷贝 / xlatb 查表路径）
实际像素 RLE：cs:[0x14b9/0x14bb/0x14bd] = @0x1977 / @0x1a3f / @0x1556（变体A）
像素拷贝原语 @0x15af：处理源 DS / 目标 ES 跨 64KB 段边界（inc 段寄存器）、bp/si 前进、行边界、裁剪
```

变体 B（@0x14bf 设 cs:[…]=0x2e24/0x2f1e/0x2868）用于水平翻转（坐标为负时 @0x1d81 `neg ax`），
其命令通过 `cs:[di+0x2ce4]` 命令指针表间接取流（跳转表 @0x28df / @0x2f12），命令语义与变体 A 相同。

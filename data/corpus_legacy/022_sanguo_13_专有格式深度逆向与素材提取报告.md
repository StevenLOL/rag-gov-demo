## 二、格式逆向分析

### 2.1 GRP 格式（地图瓦片包）

**文件头结构（8字节）：**
| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0 | 4 | magic | "GRPE" |
| 4 | 1 | version | 版本号 |
| 5 | 2 | first_size | 第一个瓦片的压缩大小 |
| 7 | 1 | reserved | 保留 |

**条目表结构：**
- 第一个条目（15字节）：`flag(1) + offset(3) + reserved(1) + w(2) + h(2) + u1(2) + u2(2) + u3(2)`
- 后续条目（19字节）：`flag(1) + offset(3) + reserved(1) + size(4) + w(2) + h(2) + u1(2) + u2(2) + u3(2)`

**关键发现：** offset 为 3 字节小端（高字节固定为 0），通过 `offset[i] + size[i] == offset[i+1]` 验证条目正确性。

### 2.2 LIB 格式（资源库）

**三种子格式（通过 magic 区分）：**
- `PIC`：TITLE/MOUSE/OFFICER/WINDOW/STORE/OBJECT.LIB（图片资源）
- `MAN`：MAN.LIB（武将头像库，6.56MB）
- `MNU`：SOLDIER/FLAG.LIB（菜单/士兵资源）

**文件头结构（9字节）：**
| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0 | 3 | magic | "PIC"/"MAN"/"MNU" |
| 3 | 1 | version | 版本号 |
| 4 | 1 | reserved | 保留 |
| 5 | 2 | first_size | 第一个资源的压缩大小 |
| 7 | 2 | count | 资源数量（MAN格式在偏移6-7） |

**条目表结构（从偏移9开始）：**
- 第一个条目（14字节）：`offset(4) + w(2) + h(2) + u1(2) + u2(2) + u3(2)`
- 后续条目（18字节）：`offset(4) + size(4) + w(2) + h(2) + u1(2) + u2(2) + u3(2)`

### 2.3 RLE 压缩算法（核心突破）

通过分析 `0F 00 0F 00 0F 00 0F 00 0F 00`（10字节）正好解码为 80 像素（5个颜色15 + 5×15=75个透明），确认算法：

```
读取字节 c:
  if c != 0:
      直接绘制 1 个像素，颜色索引 = c
  else (c == 0):
      读取 length = 下一字节
      读取 color = 再下一字节
      重复绘制 color 共 length 次（color=0时为透明）
按行宽自动换行
```

**算法特点：**
- 非零颜色值只占1字节（适合颜色丰富的区域）
- 连续相同颜色用3字节表示（标记+长度+颜色）
- 颜色0（透明）通过RLE批量跳过，极大压缩了空白区域
- 典型压缩比：80×72=5760像素 → 约1100字节（压缩比 ~5:1）

### 2.4 MAN.LIB 武将头像的精灵目录

第一个武将（offset=6089, 128×117）包含**精灵目录**，每条18字节：
`c1(1) + c2(1) + marker(1)=0x1E + reserved(1) + data_offset(4) + flags(2) + x(2) + y(2) + w(2) + h(2)`

第一个武将含18个子精灵（尺寸26×77到77×84不等），通过x/y坐标拼合成完整头像。后续武将均为单图直接RLE编码。

### 4.2 调色板

使用游戏根目录 `DEFAULT.PAL`（768字节纯RGB）作为全局调色板。**已知问题：** 武将头像和部分瓦片颜色偏色，原因是 DEFAULT.PAL 是 UI/界面调色板，武将头像可能有独立调色板（存储在 MAN.LIB 内部或游戏运行时动态加载）。图像结构完整，仅颜色映射偏差。

### 4.3 输出格式

所有素材输出为 **RGBA PNG**，透明区域（颜色索引0）保留为 alpha=0，便于后续游戏开发或素材复用。

## 五、逆向过程中的关键突破

1. **RLE算法确认**：通过 `0F 00` 重复模式的像素计数反推，确认"非0=直接绘制，0=RLE标记(长度+颜色)"
2. **条目结构推导**：通过 `offset[i] + size[i] == offset[i+1]` 的数学验证，确定14+18字节的条目表结构
3. **3字节offset**：发现GRP条目使用3字节offset（而非4字节），高字节为reserved=0
4. **首条目特殊化**：第一个条目的size存储在文件头（偏移5-6），首条目本身无size字段

## 六、已知问题与后续优化

### 6.1 已知问题
1. **调色板偏色**：武将头像和部分瓦片使用 DEFAULT.PAL 导致颜色偏差，需查找各资源独立调色板
2. **部分LIB条目误匹配**：MOUSE.LIB/WINDOW.LIB 后续条目可能为数据偶然匹配，需用count字段精确限制
3. **SOLDIER.LIB**：仅解析到1个大图，士兵动画帧可能在图内以网格排列，需进一步切割

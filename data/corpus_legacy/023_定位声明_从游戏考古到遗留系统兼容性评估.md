## 二、重新定位：这其实是遗留系统（legacy system）逆向

DOS/PC98 老游戏的资源文件具备遗留系统的**全部典型特征**：

| 遗留系统特征 | 本项目中的具体体现 | 对应文档 |
|---|---|---|
| **无文档** | 20+ 年前的自研容器格式，厂商早已不提供规格 | `003` `005` `007` `011` `012` `013` |
| **二进制黑盒** | 需靠 IDA 反汇编/反编译还原格式语义 | `399f4f2` SANGUO GRP/MAP |
| **自研/非标准编码** | RLE 变体、CMP、TIC 地图、RSK 打包、SuperYin 容器、PLK/BLK | `004` `014` `018` |
| **依赖已消失的运行环境** | DOS/VGA mode 13h、Mode X、PC-98 16 色 | `000` §2 |
| **只能在原平台正确呈现** | 调色板随硬件/模式变化，脱离环境即失真 | `000` §2.1 |
| **评估工作量未知** | 不逆向就无法判断能否迁移 | 全流程 |

**所以本项目训练的能力，本质是：把一个无规格、无源码、无社区支持的二进制黑盒，
逆向到"能在现代环境正确重现"的程度。** 这与企业/国防领域维护 legacy 系统是同一类问题。

## 三、对外表述（可直接用）

### 30 秒版

> "我逆向了十几个 90 年代国产 DOS/PC98 游戏的资源格式。这些是没有规格、没有源码、
> 运行环境已经消失的二进制黑盒——我用 IDA 反汇编确认容器与像素布局，破解它们的
> 自研压缩（RLE 变体、LZ、Huffman），定位调色板，把瓦片重组成完整地图，
> 最后产出可复现的提取脚本。目标是在现代环境正确重现这些资源。"

### 与"兼容性"的直接对应

- 格式兼容：同一游戏的多个版本（`SUPER` v1/v2/v3）容器格式有差异 → 需版本差异分析
- 工具兼容：评估 RPGViewer / QuickBMS / Camoto 等现成工具能否覆盖（**现成的 COTS 评估实例**）
- 环境兼容：DOS 图形模式（13h / Mode X / PC-98 16 色）→ 现代 RGB 的正确映射
- 可复现：`004_烈焰钢狼传_解码技术文档_可复现指南` —— 换台机器也能跑出同样结果

## 四、法律与伦理（复用 `000` §10，不另起炉灶）

`000` 已写明：DMCA 1201 条对"**互操作性**"有豁免，欧洲 InfoSoc 指令类似；
个人学习、研究、评论一般属合理使用；商业使用与公开传播需授权。

**"兼容性/互操作性研究"恰好落在豁免语义内**——这比"游戏考古"的定位在法律上更稳。
对外一律表述为：*format documentation and interoperability research*。
